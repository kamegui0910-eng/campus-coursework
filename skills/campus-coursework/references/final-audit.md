# 最终作业审计模块

## 收稿与职责

所有写作 worker 把完整可审阅成果送给总控指定的 `final-audit`：论文、Weekly Summary、Discussion 主帖与每条必要回复分别审计。审计与提交是两个角色；写作 worker 不能自行宣布可提交，审计通过也不扩大本人提交授权。

收稿包包括稳定任务键、题干/rubric及版本、截止/关闭、实际已读来源、学生已确认观点与个人事实、完整文件、可复制正文、质量记录及缺口。审计者在 `audits/{task_key}/{audit_revision}/` 保存本轮记录，可复制 [audit-record.example.json](../assets/audit-record.example.json)；各轮保留历史，不覆盖旧报告。

同时读取 [本项课程资料包](course-library.md)，核对课程/任务身份、精确章节、来源版本、必要资料完整性及最近学校要求复核。资料包为Blocked/需复核、依赖版本已更新、未核实rubric或必要章节未读时不放行。记录资料包路径、`bundle_fingerprint`（或等效依赖哈希）和各来源版本；release绑定该指纹。来源变化可能不改稿件字节，仍须复核其论证、引用和要求；脚本不会替你改写已有审计文件，审计者与提交者都须读当前索引再核对。

开始前对实际最终文件计算完整 SHA-256，固定实际受检文本并另算 SHA-256。默认受检范围为完整正文、标题及文内引用；封面和参考文献单独注明是否包含，不能检测后为了降分临时删去高分段落、引语或必需内容。检测范围在各轮保持一致；两站如因产品要求而不同，分别保存原文、范围及哈希，不能声称两份输入完全相同。

使用检测策略 `qualifying-prose-length-v2`：按实际符合Turnitin条件的正文统计真实词数，记录计数方法、文本范围、证据及选择理由。少于300词时必需provider仅为 `copyleaks`，Turnitin记 `not_required_length_exception`，不是已检测或检测通过；达到300词时必需provider为 `copyleaks` 与 `turnitin`。300词本身属于双站分支。词数未知/计数口径不明时为 `Blocked: word_count_unverified`，不能猜测单站。不能删除正文、拼接无关文本或改计数范围来选择较轻分支；正文修改后重计并重新选站。

记录学校辅助/披露规则、外发检测授权、当前正式提交 grant、题干/策略版本和审计操作者。前置内容/来源缺失先退回完善，可以有真实检测报告作参考，但不能因低分跳过缺口。

## 审计步骤

1. 核查逐题覆盖、rubric、分析与证据、准确引用、学生事实/观点、必要局限和披露、篇幅及实际逐页渲染，并读取本稿quality record中的 `skill_usage`。按 [skill-routing.md](skill-routing.md) 区分真实读取/应用、内置规则、不适用与缺失；缺记录不编造已调用。保存 pass/fail/unknown 的依据，未知不当通过；外部skill缺失本身按允许的等效规则处理，必要渲染/网页核验未完成仍不放行。
2. 读取 [detector-standards.md](detector-standards.md)，先据真实正文词数确定本稿必需provider，再核验这些站的合法入口、账号能力、文本/语言/长度要求及提交前AI报告。短文本只要求Copyleaks真实报告，但Copyleaks自身长度/语言门槛仍须满足；不满足则 `Blocked: provider_text_requirements_not_met`。达到300词的文本没有Turnitin提交前入口仍为 `Blocked: pre_submission_report_unavailable`，不能套用短文本例外或先提交真实课程作业取报告。
3. 指定浏览器操作者智能体，优先创建/复用环境实际支持的专用浏览器会话/标签组并记录返回的 session/tab ID；无此能力时读当前 Computer Use 技能和必要指导后操作。共享浏览器/桌面串行使用，不复制会话秘密，不自行实现工具不允许的浏览器控制。skill 是操作协议，不能把它当成已安装的浏览器引擎。
4. 从已冻结文本实际复制粘贴或按站点能力上传相应文件；核对输入没有截断、残留旧稿或混入提示词。Turnitin 无公开粘贴框时按本人有权使用的正式检测入口处理，不猜造控件或转交不明代查网站。仅使用已指定且授权处理正文的接收者；不擅自购买订阅、换第三方或上传其他学生文本。
5. 发起实际扫描，等待报告完成。记录站点、原始指标标签/取值/单位、解析含义、文本范围/哈希、scan/report ID、时间、模型版本（若显示）、高亮定位及原始截图/可导出报告。UI只显示不精确区间时保留区间；不捏造数字。
6. 分别判断本稿所有必需站严格 `<20%`。按词数选择出的provider ID集合核对每个站的有效当前报告；双站分支中重复两份Copyleaks报告不算齐全，单站分支必须有Copyleaks报告而不是生成模型判断。数字须在声明单位的合法范围内且非空/非NaN。有效数字19.9%可通过该站条件，20%及以上不通过；Turnitin真实官方 `*%` 只有在当前文档/界面已核验它表示低于20%时可记 `below_threshold_interval`，准确数字仍为null。必需站的空值、加载、超时、未授权、unsupported、similarity分数或“未检出报告”不能当0%。
7. 本稿必需站全部通过、所有质量项完成且版本一致时记录审计 Passed。正式提交授权有效且其余条件都满足才生成 release，交给单一提交执行者；不能求两站平均、小于20的一站代替双站分支、或挑最好的一轮。单站分支保留Turnitin长度例外与真实词数，不能写“两站通过”。

没有独立智能体工具时，在当前任务内明确切换审计阶段、记录真实操作者；不得声称已经创建独立模块/浏览器进程。具体检测选择器和结果读取以当次真实页面为准，不维护未经实测的脆弱 selector 脚本。

## 未达门槛时退回修改

将任一站的真实高亮按段落/句子定位送回原写作 worker，附上下文、原文与报告位置、可核验的具体修改理由。只把标记当需复核的线索，不把它断言为作者身份或某句一定来自AI。

依据保存的个人表达偏好、真实来源、rubric和已核验官方解释检查：表述是否空泛、是否重复或机械并列、论证是否缺具体依据、句子逻辑是否清楚、是否把引文和本人分析混在一起。可用时读取相应语言 Anti-Defensive Writing 技能。修订应让学生真实论点与证据更具体、结构更自然、句子更清楚；不能用虚构亲历、故意错误、隐藏字符、伪造引用、删除必需披露或修改检测页面/报告制造结果，也不承诺某项改写必定降低检测分数。

每轮保留原稿、新稿、差异、理由和来源。重新检查全文要求、引用与排版，重新计算当前文件/文本哈希、真实正文词数和必需provider集合，并对本轮全部必需站重新检测完整约定范围；跨过300词边界须重新选择分支。不能改了稿后沿用上一版某站的低分。若只是修改排版且受检文本、真实词数和所选分支完全相同，可保留绑定该文本哈希的真实检测报告，但须重新渲染并重新签发匹配新文件哈希的审计放行，不把旧 release 直接搬来。

默认最多三轮实质修改（初次检测加至多三轮复检），并受真实截止、已授权费用/额度和可用时间限制。连续无实质改进、报告不可靠/无法获得、达到上限或临近关闭无法完成时记 Blocked，报告实际结果和需要本人决定的事项；不会因为时间紧而越过20%条件，也不无限创建新版本/任务。

技术失败先检查已有 scan/report，再作有依据的重试，默认每站最多两次技术重试；不把同稿重复扫描挑最低值，不越过 CAPTCHA、付费或账号权限。等待使用工具允许的轮询/等待方式并保持可响应，不能为了降低分数而更换未知服务。

## 放行、失效与提交核验

审计记录至少保存：

- `audit_id`、任务键、审计者、时间和状态（Pending/Running/NeedsRevision/Blocked/Passed/Stale）。
- 稿件路径、完整文件 SHA-256、实际受检文本路径/哈希与排除范围；题干/rubric/检测策略版本，真实正文词数、计数方法/证据、选择理由及所需provider集合。
- 各项质量结果、`skill_usage`及适用rubric引用、本稿所需站的当前版本真实报告、原始值/语义/单位、明确的单站判定及证据；适用时Turnitin单列长度例外，不能当成功报告。
- 修改轮次、原文/修订差异与理由、仍未满足项、授权引用。
- release 的当前文件与受检文本哈希、audit引用、策略和要求版本、时间及可提交标志。

任一正文、引用、必需披露、题干或检测策略变化，将旧 release 置为 Stale；文件变化至少使旧文件放行失效。提交执行者在发出正式动作前重新计算当前哈希并核对 audit、grant和窗口；不匹配就退回审计，不能凭聊天里一句“已经通过”提交。

资料包指纹或当前来源版本与release不一致、依赖复核未完成时同样停止正式动作。已经有效提交的内容只保存变更影响，不自动重交。

真实提交后保留回执并记录所用 audit ID，审计报告与学生作业分开保存。不要把内部报告或检测截图附进正式作业，除非题目/本人明确要求。
