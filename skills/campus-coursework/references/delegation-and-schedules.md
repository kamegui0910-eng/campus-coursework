# 作业分工与定时推进

## 按真实工作选择职责

| 职责 | 主要产出 | 持久写入范围 |
|---|---|---|
| 总控 | 大纲基线、冲突、任务索引、依赖、汇总和排程映射 | handbook、tasks/index、schedules、grants |
| 教材阅读 | 实际已读内容、定位、当周资料包与缺口 | reading manifest 和笔记 |
| Discussion | 主帖、针对真实同学内容的必要回复 | 自己的状态和讨论草稿 |
| Weekly Summary | 目标、概念与真实课堂/视频的总结 | 自己的状态和总结成稿 |
| Writing/Project | 逐题覆盖、研究证据和分析 | 自己的状态、研究和成稿 |
| Assessment Preparation | 规则核验、概念解释、练习与复盘 | 自己的状态和学习资料 |
| 最终审计 final-audit | 统一收稿、具体 rubric/来源/渲染检查、按真实词数选站的报告、退回修改和版本放行 | audits、quality record 与 release |
| 提交执行 | 核对有效授权及匹配版本的审计放行；正式回执 | submissions |

简单课程可在一个任务内兼任；大项目按独立成果拆分，不要求每门课新建整套空聊天。质量检查可委派只读审阅；正式发布/提交保持单一执行者。不要将普通作业自动提交授权扩展到考试、独立完成声明或小组成员代签。

各写作 worker 完成后必须送指定最终审计者，不能直接送提交执行者。优先让独立审计智能体使用专用的受支持浏览器会话操作检测站，共用桌面时串行；没有独立智能体能力时在同一任务中显式切换到审计阶段并记录实际操作者，不虚构独立审计。审计按 [final-audit.md](final-audit.md) 操作，任一不满足项具体退回原 worker；最多三轮后仍不满足则保持待审，不能改门槛、遗漏站点或无限循环。

交接包至少包含：学校/课程/学期与任务唯一键、真实题干/rubric/附件位置、原始截止和关闭时间及 IANA 时区、阅读依赖状态、已读来源与未核验缺口、真实个人材料范围、适用授权、允许写入目录、成果版本和下一步。按 [worker 提示词模板](../assets/worker-prompt.md) 生成具体内容，不把密码、Cookie或所有聊天历史贴过去。

按 [课程资料库](course-library.md) 附本项资料包与依赖版本，只传指定 chapter/section/page、当周真实课堂材料和适用政策。同名不同周的作业不能按标题复用资料。资料索引由指定负责人单写；变更后通知受影响 worker 复核已有稿件与审计，已提交任务不自动重交。

可用当前环境的 subagent 做并行研究/起草；需要持久聊天时用可用任务工具创建并记录实际 ID。创建本身不代表 worker 已读材料或完成成果。给现有聊天发消息要满足本人授权及工具规则，不能用 subagent 消息工具冒充已向某个外部/历史聊天发送。

## 建排程之前

只有使用者请求定时、持续监测或自动推进时才创建实际排程。用户只是让你设计/分享 skill 时不启用任何课程循环任务。

先枚举当前环境已有排程，按学校、课程、职责、目标任务、执行时间与 prompt 识别重复，优先更新匹配项。历史本地 manifest 只供定位，不证明服务端当前状态；不导入原作者 automation ID。

先在普通执行中核验工具和来源，再排程。根据真实 due 和 close 倒排：阅读 → 起草 → 最终审计/按真实词数选站检测 → 必要修改与重新检测 → 本人审阅（需要时）→ 授权提交 → 回执检查。为检测服务排队和有限修改预留实际缓冲；达到300词的双站分支若Turnitin只有交后报告，提前记录门槛不可执行，不能冒充短文本例外。内部缓冲与教师截止分开记录，已过内部时间则立即处理，不等待下个周期。不同截止/授权分开的任务可以共用一个循环 worker，但必须逐项核对状态。

可采用的初始节奏（仅按课程实际情况选择）：周初核对本周模块并读书，讨论主帖截止前留足研究时间、回复截止前读取同学帖，论文提前起草，周末检查未完任务。若星期三已有作业到期，就不能只用星期日检查。多门课错峰，减少共用登录/桌面冲突。

教材较早启动只是时间安排，不是任务依赖保证。消费者执行时读取 manifest 的版本与 Ready/Partial/Blocked 状态；Partial 时核验自己能补齐的部分，缺必要内容则记录缺口，不假写已读或等到逾期。

## 用实际调度工具创建

动态发现并读取当前调度器工具文档；其参数、目标限制和权限以实际文档为准。Codex app 当前有 recurring automation/heartbeat 能力时，优先沿同一任务续跑；只有用户要求每次独立任务或独立项目工作时选择对应 standalone 模式。工具不可用则交付具体待启用计划，不用 shell cron 或后台常驻脚本冒充已创建的应用排程。

提交给调度器的 prompt 使用清楚连贯的工作指令，显式调用 `$campus-coursework` 并指出私人配置、课程和 worker 文件路径。不要把外部用户的授权文字硬编码为通用许可。提示词必须包含：

1. 每次先读配置、授权、课程手册、worker 状态、阅读清单与本 skill；核验当前日期/课程/term。
2. 核对真实新要求与已有提交，同步本项 rubric、附件、指定章节和新发布模块，更新课程库依赖；只取本项相关资料，不能把以前全量下载当成无需刷新。推进本职责内实际到期工作；明确单一写入范围。
3. 所有成稿先回最终审计者；按真实符合条件的正文词数选站：少于300词仅Copyleaks，达到300词Copyleaks与Turnitin。提交仅由指定执行者依据有效grant、QA及绑定当前版本/真实词数/所选provider集合的审计放行进行。本稿任一必需站未达严格低于20%条件则不提交，Copyleaks自身输入要求仍须满足；异常先核查，不重复发送。
4. 真实结束日期后不继续内容工作，停用本课专属排程；共享排程只移除该课。
5. 返回具体进展、路径和缺口，不把检查无变化写成已完成作业。

通知选项若有专用字段，使用该字段；不要假定在 prompt 写“安静”就改变系统通知设置。按当前工具规则生成排程参数，不手改调度器内部配置文件。

创建/更新后核验工具返回的 ID、实际目标/项目、prompt、执行环境、状态、时区与 next run。工具没有返回时区/下次运行时，通过可用 view 或 UI 再核查；无法验证就写未核验，不能把期望值当实值。RRULE 等内部格式无需展示给一般使用者。

## 环境限制与恢复

本地学校浏览器、私人文件和本地 skill 需要相应机器与应用在运行，且会话/权限有效；云端任务不能假定能读本地目录或继承桌面登录。若切换云端，要明确共享数据位置及可用连接器，不上传学校/个人资料来默默弥补能力差异。

定时器保存成功不等于任务已运行，更不等于完成或提交。记录每次实际开始、来源核验、产出、错误和完成状态；登录过期时完成本地可用工作，并只在确需本人操作时提醒。

创建或提交返回超时先查现存排程/提交；不能反复创建。课程结束后归档成果、回执和来源，停用只属于该课的任务。停用失败则报告调度 ID 与错误，后续触发先检查结束日期并拒绝继续课程内容动作。
